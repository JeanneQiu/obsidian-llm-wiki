# Jean 的层级学习笔记

此本地版本基于 GD4AI/obsidian-llm-wiki 1.28.0（c47c25a）修改。没有发布到上游。

## 使用

在原插件设置底部启用“层级学习笔记模式”，保存并重新加载插件。
继续使用原有摄入单份资料、文件夹、多文件或当前文件的命令。
PDF、图片和 Office 文件继续走原插件的文档转换后端；MinerU Token 保存在原有 SecretStorage 槽位。
模型仍在原设置中选择，当前使用 Magpie 的 `deepseek/deepseek-flash`。

模型分两步工作：先根据已有知识页和目录规划主题路径，再读取选中的旧笔记并合并摘要与知识细节。
长资料按 24,000 字符逐块处理，不截掉尾部；规划目录清单与选中旧笔记有上下文上限，超限时明确报错。
没有固定的领域树，也不会自动删除或移动已有笔记。手工建目录与移动文件后，后续规划读取最新结构。
选择当前文件摄入可以主动重新整理；文件夹批次会跳过内容没有变化的资料。

每层 `index.md` 由程序生成，只列当前子目录与文件。没有摘要、阅读顺序或待补充内容。
创建、移动、重命名和删除笔记后，目录会在约 1.2 秒后重建；也可以运行原有“重新生成索引”命令。
新增“打开层级知识目录”命令。

知识文件：`Jean's Wiki/领域/主题/笔记.md`。
解析正文：`Jean's Wiki/原始资料/资料名-内容哈希.md`，链接回原始 PDF 或 Markdown。
摄入历史：仍用原 `log.md`，原历史界面可读取。
改写旧笔记前的副本：`Jean's Wiki/.jeans-wiki/backups/时间戳/原路径.md`。
整理状态：`Jean's Wiki/.jeans-wiki/state.json`。这些隐藏文件不进入知识查询。

允许模型改写手工笔记；但如果笔记在模型调用期间被编辑或移动，本轮停止并提示重试，避免使用旧快照覆盖新编辑。
模型输出路径、JSON 格式、输出是否截断都在写笔记前验证。备份写入失败时不改写旧笔记。
文件写入不是跨文件原子事务；磁盘故障或强制退出可能留下部分结果，备份可用于恢复。

查询仍复用原来的图谱与关键词检索，层级笔记按实际路径加载；引用提示不再限定 concepts/entities。
查询中的保存对话也进入层级整理流程。原模型设置、MinerU 转换缓存和取消按钮均保留。
原概念模式的 Lint、Schema 模板和标签设计未改造成层级目录编辑器；日常目录维护使用索引命令。

## 维护

插件市场更新会覆盖本地定制代码。更新前保留此源码与补丁，再合并上游改动。
关闭层级模式可回到原摄入流程；已有层级 Markdown 文件仍保留。

## 实现位置

- `src/wiki/hierarchical-notes.ts`：主题规划、合并笔记、原转换器调用、备份和简洁目录。
- `src/wiki/wiki-engine.ts`：原摄入入口和对话保存的分流、历史日志、取消处理。
- `src/main-commands/command-registry.ts`：打开目录命令、文件结构变化后重建目录。
- `src/schema/auto-maintain.ts`：层级模式启动时更新目录，不按旧分类修复。
- `src/wiki/query-engine/pipeline/assemble-context.ts`：引用实际笔记路径。
- `src/__tests__/wiki/hierarchical-notes.test.ts`：路径验证、合并、备份、移动、取消和可选真实 Magpie 测试。

本地改动的 CPU 主要为目录扫描；模型并发沿用原批次安排。目录只需文件名，不调用模型。
初次规划读取上游页面索引，正文只加载选中的知识页。长资料每块至少两次模型调用，模型调用量随资料长度增加。
备份会持续占用本地空间，不自动清除。
